# 去識別化平台操作手冊

> 回到 [README](../README.md)

## 1. 系統簡介

本平台在本機偵測並去識別化檔案中的個人資料（PII），資料不需上傳到外部服務；LLM 使用本機 Ollama。

- **結構化資料**：xlsx、csv。逐欄選擇處理方式，並可做 k 匿名。
- **非結構化文件**：docx、pdf（文字型 PDF）。以規則、中文 NER（CKIP）與本機 LLM 偵測，輸出去識別化後的 docx／PDF。
- **報表**：每次處理後提供各欄位或各項目的處理方式與結果。

| 檔案 | 用途 |
| --- | --- |
| `app.py` | FastAPI 後端，負責上傳、偵測、去識別化、輸出 |
| `去識別平台.html` | 前端操作頁面 |
| `detection.py` | 規則式偵測 |
| `llm_detector.py` | 呼叫本機 Ollama 的 LLM 偵測 |
| `kanon_adapter.py` | k 匿名介面（串接 ANJANA） |
| `登入.html` | 登入頁 |

## 2. 安裝與啟動

必須使用 Python 3.12：ANJANA 鎖定 numpy 2.0.2／ pandas 2.3.3，這兩個版本在 Python 3.13 以上沒有現成套件，會在安裝時嘗試編譯而失敗。

1. 建立虛擬環境（只需一次）：

```bash
cd D:\去識別化
py -3.12 -m venv venv312
venv312\Scripts\activate
```

2. 安裝套件（在已啟用的 venv312 內）：

```bash
pip install fastapi uvicorn python-multipart python-docx pdfplumber pypdf reportlab requests pandas openpyxl
pip install anjana pycanon
# 選用：中文 NER（體積大，安裝需數分鐘）
pip install ckip-transformers torch
```

3. 確認 k 匿名套件可用：

```bash
python -c "import anjana.anonymity, pycanon.anonymity; print('OK')"
```

4. 啟動後端（一定要用 `python -m`，避免跑到系統全域的 uvicorn）：

```bash
python -m uvicorn app:app --reload --port 8000
```

5. 若要使用 LLM 偵測，先安裝 Ollama，再拉取模型：

```bash
ollama pull qwen2.5:7b
ollama list
```

6. 用瀏覽器開啟 `去識別平台.html`。更新前端後請按 Ctrl+F5 強制重新整理。

`pip` 顯示 `typing_extensions` 版本衝突警告通常可忽略，只要第 3 步印出 OK 即可。

## 3. 基本操作流程

不論檔案類型，都是「上傳 → 偵測 → 確認 → 下載」四步。

1. **上傳**：開啟頁面，選擇 xlsx、csv、docx 或 pdf。
2. **偵測與分析**：系統掃描內容，進度條顯示階段。非結構化文件可勾選是否使用 LLM。
3. **確認面板**：列出偵測到的欄位或項目，讓你修改處理方式、取消誤判，結構化資料可在這裡設定 k 匿名。
4. **執行去識別化並下載**：按確認後產生結果檔，頁面同時顯示報表（每個欄位或項目的處理策略）。

結果檔的暫存時間有限（預設約 10 分鐘），請完成後立即下載。

## 4. 結構化資料（xlsx／csv）

系統以欄位為單位偵測敏感欄，你在確認面板為每一欄選擇處理方式。

- **刪除欄位**：整欄移除，適用於姓名、身分證字號等直接識別碼。
- **雜湊（hash）**：同一值得到同一代碼，可保留「同一人」的關聯，但無法還原。
- **遮蔽（redact）**：以符號取代內容。
- **k 匿名泛化**：用於「單一欄位不算識別到人，但組合起來可能導致識別」的欄位，見第 5 節。

被設為刪除、雜湊或遮蔽的欄位，會自動排除在 k 匿名運算之外，避免重複處理。系統目前只讀取第一個工作表。

若資料中有英文值（例如 female、taipei），系統的縣市泛化可辨識完整英文縣市名；縮寫（如 tai）不支援，性別若混用多種寫法，請先在原始資料統一。

## 5. k 匿名

k 匿名要求「每組準識別碼組合至少有 k 筆相同的資料」，例如 k=5 代表任何一筆記錄至少跟另外 4 筆無法區分。系統使用 ANJANA 泛化與抑制，用 pyCANON 計算 k。

### 操作步驟

1. 在確認面板勾選「我要做 k 匿名」。
2. 設定 **k 值**（預設 5）與 **最多刪除比例**（允許被抑制的記錄比例）。
3. 在每個欄位勾選「準識別碼」：單看不足以識別、但組合可能識別的欄位，如年齡、性別、郵遞區號、居住縣市。
4. 需要「一律泛化」的欄位再勾選「固定泛化」。勾選固定泛化會自動勾上準識別碼。
5. 執行後查看結果方塊：k 值、被刪除的筆數，以及每欄泛化到哪一層。

### 泛化規則

| 欄位類型 | 預設泛化方式 |
| --- | --- |
| 數值（如年齡） | 區間，寬度依序為 2、5、10、20、50、100、500、1000 |
| 日期 | 年月 → 年 |
| 郵遞區號／數字代碼 | 數字區間 |
| 縣市／地址 | 北部、中部、南部、東部、離島（地址在離島則為「離島」） |
| 性別等類別值（≤ 3 種） | 合併為「男/女」這類集合標籤 |
| 其他類別值 | `*` |

「固定泛化」會先把該欄一律套到上表的第一個區域／集合層（縣市→區域、性別→男/女、年齡→`*`），不論 k 是否達標。若 k 還沒達標，系統仍可能再往上泛化，所以最終結果可能比你設定的更粗。若想把年齡保留為區間，請只勾「準識別碼」，不要勾「固定泛化」。

縣市分區依國土計畫分類（苗栗屬北部、宜蘭屬東部），可在 `kanon_adapter.py` 的 `REGION_OF_COUNTY` 修改。

### 可能看到的結果

- **準識別碼全變 `*`**：資料列數不足或組合太細。例如 40 筆資料搭 4 個準識別碼，幾乎無法達到 k=5。
- **某些列被刪除**：不屬於任何達標群組的記錄，在「最多刪除比例」的範圍內被抑制，這是以缺資料換取其他欄位不被過度泛化。
- **空結果或錯誤**：即使泛化到最高層仍無法達到 k，系統會顯示錯誤訊息。請降低 k、減少準識別碼或提高刪除比例。

目前不支援 l-diversity；Word 文件內的表格也可做 k 匿名，但不會刪除列。

## 6. 非結構化文件（docx／pdf）與 LLM 偵測

系統組合三層偵測：規則（手機、身分證、Email 等）、CKIP 中文 NER（人名、地址）、本機 LLM（規則押不到的語意型資料）。

- **性別**：除了欄位型寫法，也能偵測敘述中的性別（例如「王小明先生」「她是女性」），多人文件可同時找出多個。規則押不到的，交由 LLM 辨識。
- **確認面板**：逐項顯示偵測結果，可取消誤判或改變處理方式。
- **PDF 輸出**：以 pdfplumber 讀取版面、ReportLab 重繪，盡量保留原版面；掃描型 PDF（圖片）不支援。

### LLM 設定與速度

- 模型建議選小型、非中國製的模型（例如 gemma3:4b）以提高速度；目前設定為 qwen2.5:7b。若有合規考量請自行更換。
- 這些模型對長文件這類工作較慢，可以取消勾選 LLM，改只用規則＋NER。
- 逾時、重試次數、單次送出的文字上限都可在 `llm_detector.py` 調整。
- Ollama 回傳 404 代表模型名稱不存在，請用 `ollama list` 確認後設定 `OLLAMA_MODEL`。

### 重新上傳同一份檔案

系統會暫存偵測結果，同一份文字在時限內重新上傳可立即產生結果，不需再跑 LLM。暫存只保存「類型＋起訖位置」，不保存原始文字，詳見第 8 節。

## 7. 設定與環境變數

在啟動後端的終端機先設定環境變數，再執行 uvicorn（PowerShell 範例：`$env:OLLAMA_MODEL="gemma3:4b"`）。

| 變數 | 用途 | 預設 |
| --- | --- | --- |
| `OLLAMA_MODEL` | LLM 使用的 Ollama 模型名稱，須與 `ollama list` 相符 | 見 `llm_detector.py` |
| `DEID_CACHE_TTL_SECONDS` | 偵測結果暫存秒數；0 表示關閉暫存 | 600 |

暫存最多保留 8 筆，超過會淘汰最舊的。處理工作的結果約 600 秒後清除。

## 8. 資安注意事項

- **資料不出本機**：偵測與 LLM 都在本機執行，沒有送往外部服務。
- **暫存不含原文**：偵測快取的鍵是文字的 SHA-1 雜湊，內容只有每個項目的類型與起訖位置，且有效期限（預設 10 分鐘），重新上傳時再從最新文字還原。
- **結果檔約 10 分鐘後清除**：完成後請即時下載，不要留在伺服器。
- **API 目前沒有驗證**，且 CORS 設為 `allow_origins=["*"]`，只適合開發與單機使用。若要供多人或內網使用，請先加上登入驗證，並把 CORS 限縮到特定網域。
- **僅綁定本機**：啟動時不要用 `--host 0.0.0.0`，除非已完成上述防護。
- **原始檔與結果檔**：去識別化前的原始檔仍含個資，請依公司規範保管或銷毀。

## 9. 常見問題與疑難排解

| 現象 | 原因 | 處理 |
| --- | --- | --- |
| 顯示「尚未安裝 anjana」 | 後端用錯 Python（常見是 3.13 全域的 uvicorn） | 啟用 venv312，用 `python -m uvicorn` 啟動 |
| `No module named 'pycanon'` | 缺 pycanon | `pip install pycanon anjana`（不要加 `--no-deps`） |
| anjana 安裝時 numpy 編譯失敗 | Python 3.13/3.14 沒有相容的現成套件 | 改用 Python 3.12 建立 venv |
| Ollama 404 `/api/generate` | 模型沒拉取或名稱不符 | `ollama list` 確認後設定 `OLLAMA_MODEL` |
| LLM 跑很久 | 模型太大或文件太長 | 換小模型、取消勾選 LLM、調低逾時與重試 |
| 結果準識別碼全部是 `*` | 資料太少或準識別碼太多 | 增加資料量、降低 k 或減少準識別碼 |
| 已勾「固定泛化」但欄位仍原樣 | 先前版本需同時勾「準識別碼」 | 更新前端後按 Ctrl+F5；新版勾固定泛化會自動勾準識別碼 |
| 重新整理後頁面仍是舊版 | 瀏覽器快取 | Ctrl+F5 |

## 10. 已知限制

- 只讀取 xlsx 的第一個工作表。
- 不支援掃描型 PDF（無文字層）。
- 不支援 l-diversity，只保證 k 匿名。
- 英文縣市縮寫、混用的性別寫法需先在原始資料統一。
- 「性別」的 LLM 偵測還沒有用真實 Ollama 完整驗證。
- API 無驗證，不適合直接對外開放。
